# 严谨技术写作

## 基调

论文式书面语，平实严谨。读者是工程师和初学者：先交代背景和术语，再展开机制细节，最后给结论。比喻只用于概念引入，不用于论证。会话里的问答和代码分析不按本 skill 执行；成文的文章、文档按本 skill 执行。

## 正文契约

成文段落满足以下形态，不满足即改写：

1. 标题用名词短语，不用疑问句；标题要脱离正文单独成立，在目录和检索结果里能看懂
2. 陈述句，主谓完整；正文不用冒号引导句式（"注册入口：xxx"改为"注册入口是 xxx"）。图后说明同样直接陈述，不加"读图："这类标签，主语写明所指（"图中虚线表示 Message 的移交方向"）；列表和代码块前的引导句保留冒号
3. 因果链完整，中间推导不省略。不写"锁内执行会死锁"，写"enqueueMessage 需要获取队列锁，next() 持有同一把锁，锁内调用 queueIdle 时回调再调 post 即构成锁重入等待"
4. 结论标注源码位置（文件:行号），无源码依据的结论标注"待验证"。描述源码动作用源码里的动词，不自创压缩词或比喻术语（"读空"→"执行一次 read"，"摊薄高频创建销毁"→"避免反复分配和回收"，"免疫屏障"→"不被同步屏障拦截"），拿不准时先读源码确认动作
5. 正文和列表用文字表达关系，不用符号速记（"callback > mCallback > handleMessage"→"依次尝试 callback、mCallback 和 handleMessage"，"屏障 = target 为 null 的消息"→"屏障是一条 target 为 null 的消息"）。图内标签受排版宽度限制，可保留符号速记
6. 术语首次出现用一句话说明含义，如"eventfd（内核提供的计数器型文件描述符）"
7. 分层组织：小节加短段落，每段只承载一个概念或一个转折
8. 上句主语明确后，下句用"它""其"或省略承接，不重复主谓宾

## 口语词替换表

| 口语 | 书面 |
|------|------|
| 拿着锁 / 放锁 | 持有锁 / 释放锁 |
| 跑 / 干活 | 执行 |
| 盯着 / 看着 | 阻塞在 / 监听 |
| 蹭进 / 塞进 | 注册进 / 加入 |
| 没消息 / 还没到期 | 队列为空 / 尚未到期 |
| 回不去 / 等它 | 无法返回 / 等待回调结束 |
| 短活 / 短任务 | 短耗时任务 |
| 一坨 / 一大堆 | 一段 / 多个 |

拟人词（"锁被占住""很克制"）改写为主谓明确的动作描述。

## 禁用项

- 模态词和填充词：需要说明的是、值得注意的是、换句话说、本质上、实际上、正是、本身
- 结构化标签：两层根因、三个维度、四步流程
- 辩护句式（"为什么 X 不 Y，反而是 Z"）和对称排比（"既不是……也不是……而是……"）
- 段首架全局（从整体来看、总的来说）
- 路标式开场（"先记两条大原则，再看几处取舍"、"下文将分三方面"），直接以主题句进入正文
- 口诀式压缩排比（"Handler 发、MessageQueue 存、Looper 取、Message 载"），角色分工写成完整主谓句
- 反问句、感叹号、"我们"作主语、破折号插入语
- 表格只用于真正的对比场景（A vs B、修改前后）；证据用列表
- 说完了就停，不重复兜底

## 自检流程

1. 对照替换表逐词排查，命中即改
2. 对照禁用项逐条排查
3. 回溯因果链：每个结论往前找，中间推导是否都在文中
4. 标题测试：只看目录里的标题能否明白本章内容
