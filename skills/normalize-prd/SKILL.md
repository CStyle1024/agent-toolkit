# 规范化 PRD

将原始产品材料整理成产品可核对、研发可继续细化的 PRD。规范化不等于替产品补完决策，也不等于生成 SRS、design、实施任务或代码。

## 输入和输出范围

先明确原始材料、允许使用的补充来源、要新建还是更新、输出位置及本次只需草稿还是需继续澄清。能从任务和项目约定确定的内容直接采用，不重复询问。按用户指定位置写入；未指定时沿用项目文档约定，没有约定则说明拟用的项目内路径。更新已有文件先读取，保留编号与已有结论。

仅使用允许的来源。用户限定“只根据 PRD”时，不把代码、历史会话、其他规格或旧实验结论当成产品依据。引用的子文档缺失或不在允许输入范围时，登记外部依赖，不从记忆或实现补写。只有实际读取过的图片/附件才作为已核对证据。

保留原始材料。按项目需要记录可定位的来源、版本、章节和确认依据；不默认生成多套快照、哈希清单或额外目录。用户要求只生成草稿时，完成带开放问题的草稿，不强制先完成全部问答。

## 组织产物

使用 [通用模板](assets/normalized-prd-template.md) 作为默认结构；用户/组织的模板优先。按材料规模裁剪，不为填满章节发明内容。

- 分清原文直接规定、整理推导、明确确认、新建议和未知。角色/场景可从材料组织，但标注推导，不能新增功能、优先级或指标。
- 功能需求按业务相关性分组，采用横向表格。保留稳定编号；移动分类不重排编号，拆分使用子编号并保留映射。
- 各行分开写需求陈述、来源、明确程度、需求状态、待澄清内容和问题编号。适用说明不冒充未决问题；缺口登记不冒充实现要求。
- 文案、条件或能力的复杂分支放专项矩阵，正文选择一处维护，其余引用；没有依据的分支保持未定义。
- 产品目标、范围、流程、交互、异常及产品验收写入 PRD。内部类、线程、存储、算法实现等留给软件规格或设计；原文明确给定的技术约束应保留，不因名称技术化而删掉。
- 明确唯一维护正文。合并旧提取稿后修正入口及回写说明，旧稿作为输入/历史，不让多个文件同时自称现行正文。

## 需求状态

| 状态 | 使用条件 |
| --- | --- |
| 已明确 | 当前适用来源表述清楚、无冲突且未实质改写，直接继承，不重新逐条审批 |
| 待澄清 | 有真实歧义、冲突或缺失条件，尚不能给出确定规则 |
| 待确认 | 已提出具体补充、解释或变更建议，但未获明确接受 |
| 已确认 | 补充或修改已获明确接受，有可定位依据 |

来源是否适用、是否完成组织签核单独如实记录，不编造批准，也不因缺少正式签核就要求所有原文要求重新确认。对混合条目先分离明确要求与未定细化；不要让后续工程细节未定阻塞整条原文的继承。

有冲突时标明冲突位置和影响，不能只按材料日期较新就认定其覆盖全部旧要求。原文未列的能力不直接写成已批准排除项。未知异常不自动选择放行、拒绝、重试或忽略。

## 澄清和回写

先检查允许范围内是否已有明确答复；真正影响产品行为的问题才提问，按重要性集中或逐项推进，服从用户希望的节奏。建议明确标为建议，不能用工具生成的文字当作用户确认。

收到答复后只在实际覆盖范围内更新：

1. 记录确认依据、适用范围和与原文的差异。可在现有记录或 PRD 变更节维护，不强制额外创建决定文档。直接继承原文的“已明确”不需要虚构确认记录。
2. 改写对应当前需求陈述及专项矩阵；不是只在文末追加新结论。部分答复仅解决部分问题，不能把整个功能标为已确认。
3. 同步受影响的用户场景、主流程、异常/边界说明、产品验收预期、来源追溯和问题表；不能只改需求行而让场景仍引用已经取消的条件。已解决问题保留编号、结论和依据，部分解决保留剩余内容；不把验收预期写成执行通过。
4. 条目被取消、替代或仅在部分范围不再适用时，保留编号和变更关系，明确本期是否仍需验收；生命周期/适用状态不与“已明确/已确认”等清晰与确认状态混为一谈。原有明确/确认规则有新变更建议时，保留现行基线与建议的区别；未经接受不悄悄替换生效规则。

## 交付前核对

按实际材料核对，不以“章节齐全”代替内容检查：

- 需求和图稿/正文有来源对应，重复、删除线旧方案和矛盾得到正确处理；未读取的依赖仍明确登记。
- 待澄清条目有具体问题关联；已明确/已确认条目不挂未解决的本条行为问题。相关大功能尚有其他问题时关联对应条目，不强制整组统一状态。
- 需求表、场景表、流程与异常说明、专项矩阵、问题状态、追溯和验收条件一致；确认后再沿需求影响范围检查旧条件是否仍被当作待决事项。原文给定的时间/数量边界和条件组合不被擅自改变。
- 没有虚构签核、误把局部确认扩展到管理员/其他用户/其他能力等未讨论对象，也没有导入项目外的业务默认值。
- 入口及回写指向唯一现行正文。报告本次仅完成结构草稿、仍有澄清事项还是已有基线依据；不自行宣称产品基线获批。

交付当前 PRD 路径、主要整理内容、关键开放问题和未核对来源。本技能不自动提交、推送、安装外部工具或开始代码开发。
