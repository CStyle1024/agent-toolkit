# Android / 车机需求缺口检查

只选择与当前功能有因果关系的检查项。此清单帮助发现问题，不授权新增功能，也不是每份文档必须填满的问卷。已有明确答案时引用原文，不重复询问；平台机制不确定时标为待技术核实，不靠记忆修订产品要求。

| 相关行为 | 可检查的缺口 |
| --- | --- |
| 应用识别与安装来源 | 系统应用、系统签名、预装、官方渠道是否分别定义；未知来源、升级、卸载更新、重装是否改变判断 |
| 声明、申请、授权、实际使用 | 是否区分静态声明与动态行为；多个条件的 AND/OR、同一应用/服务归属、观察窗口和失效条件 |
| 权限撤销与特殊访问 | 原文业务权限清单映射哪些授权；普通权限、AppOps、特殊访问、无障碍启用状态是否适用；不可撤回、部分失败与用户可见结果 |
| 风险标签、去重、限频 | 作用域按包、安装实例、版本、Android 用户还是设备；重启、休眠唤醒、清数据、重装何时重置；车机上电周期如何界定 |
| 通知与处置 | 首次/再次触发、应用可卸载性、系统/三方文案和按钮分支、送达与已通知的区别、点击后结果、失败与并发；原文无二次确认规则不擅自改写 |
| 行车状态 | 收纳与发送区别、行车/驻车切换、通知频次计算；只在原文涉及行车交互时检查 |
| 名单、保护对象、豁免 | 包/宿主/小程序/页面身份，谁维护及何时生效；系统身份与签名权限区分；豁免覆盖哪些能力，不默认全放行 |
| 用户与窗口边界 | Android 用户/访客/资料、多屏/分屏/画中画、焦点与可见窗口；聚焦会改变本功能结果的情形 |
| 无障碍、截图与采集 | 节点读取、窗口列表、事件、操作、手势、无障碍截图、MediaProjection 分别保留返回/失败规则；不把截图失败、黑图和局部遮挡视为同一结果 |
| 生命周期与异常 | 应用/服务/名单变化时已生效状态与进行中操作如何处理；失败、部分成功、依赖不可用时产品期望；NA 不等于不存在异常 |
| 平台适用性 | 原文涉及的 Android/FlymeAuto 版本、设备能力、权限类型是否已明确；仅在会影响产品行为或验收时追问 |

问题措辞示例：原文已写“撤回清单内已授予权限”时，保留该规则，问“清单的具体授权映射和不可撤回时的反馈是什么”；不改问“是否只撤回与本次风险相关的权限”。
